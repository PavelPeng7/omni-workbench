# Domain documentation

This is a single-context plugin rather than a monorepo.

- Read `CONTEXT.md` before changing task, timer, note-triage, or release terminology.
- Put system-level architecture decisions in `docs/adr/`.
- Put approved buildable specifications in `docs/specs/`.
- Update existing terms instead of introducing synonyms for the same concept.

Create an ADR when a decision changes a persistent data shape, plugin boundary, module seam, compatibility promise, or release contract and would be costly to reverse.
