# Issue tracker

Use GitHub Issues in `PavelPeng7/omni-workbench` for executable work.

## Flow

1. Confirm a spec under `docs/specs/`.
2. Create tracer-bullet tickets that each deliver an end-to-end, verifiable slice.
3. Record blocking relationships explicitly and work only unblocked tickets.
4. Incoming reports may be triaged with `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, or `wontfix`.
5. Close a ticket only after its acceptance criteria, quality gate, and Standards + Spec review pass.

Do not create remote labels or issues during planning without explicit confirmation of the proposed drafts.
