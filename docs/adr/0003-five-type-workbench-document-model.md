# Five-type workbench document model

Tasks, projects, fleeting notes, literature notes, and permanent notes are peer workbench-document types. Project workspaces live under `Omni Workbench/项目/`. Projects are parents: each owns a workspace directory containing `项目.md` and a `任务/` subdirectory of child tasks, and every new-model task belongs to exactly one such workspace. Project assignment is a physical task move between project workspaces. Path is authoritative, while `所属项目` is a compatibility mirror. The directed knowledge conversion workflow is fleeting→literature→permanent, fleeting→task, fleeting→project, task→fleeting, and project→fleeting. A focused or timed task cannot be converted, and a project with child tasks cannot return to a fleeting note. New task and project documents use this model; pre-workspace task and project documents are left untouched and are neither migrated nor recognized by it, except when a user explicitly converts one to a fleeting note. A recognized `type` frontmatter value is authoritative; configured folders are destinations and only infer the type of legacy files lacking a valid value. A conversion changes and relocates the original file, retains common content and archived incompatible metadata, initializes the target type's required fields, and resolves a destination-name collision without overwriting a vault entry. Each type has a configurable template. This replaces the prior three-type knowledge-only conversion boundary so that the Workbench has one coherent document model while retaining the task execution surface and its existing workflow.
